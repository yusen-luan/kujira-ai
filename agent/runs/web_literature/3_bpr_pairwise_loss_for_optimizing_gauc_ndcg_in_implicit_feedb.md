Yes — Bayesian Personalized Ranking (BPR) is the well-established, widely-used pairwise loss for this exact setting: it directly maximizes the probability that an observed (positive) item is ranked above an unobserved (negative) item *for the same user*, which is mathematically the per-user pairwise comparison that GAUC measures, so BPR-style training tends to track GAUC/nDCG more faithfully than pointwise BCE, which only calibrates per-example probabilities and ignores within-user ordering. It is cheap: for each training step you sample one positive and one negative item from the *same user's* impressions (not global negative sampling), compute `score(pos) - score(neg)`, and apply `-log(sigmoid(diff))`; this is O(1) extra work per pair beyond a normal FM forward/backward pass and needs no expensive candidate retrieval, so it fits comfortably in a small numpy/torch CPU per-epoch budget. In-batch variants are also practical — you can build positive/negative pairs within a shuffled mini-batch grouped by user_id (vectorized via index masks in torch), avoiding any per-user Python loop. Caveats found in follow-up literature (not from the source_url, so not independently verified here beyond publisher attribution): the ACM TOIS paper "On the Effectiveness of Sampled Softmax Loss for Item Recommendation" (Wu et al., ACM TOIS 2023) reports sampled/in-batch softmax listwise losses can outperform BPR on some benchmarks but are more sensitive to the number of negatives; and the ACM RecSys 2023 paper on gSASRec (dl.acm.org) warns that naively using in-batch negatives with plain BCE causes overconfidence and metric degradation, which is why BPR's explicit pairwise formulation (or sampled-softmax) is generally preferred over BCE-with-in-batch-negatives. For a KuaiRand-Pure-style sparse, popularity-skewed short-video setting, sampling negatives *within the same user's impression list* (rather than globally) is especially important so popular items don't dominate the negative pool and bias the pairwise gradient.
