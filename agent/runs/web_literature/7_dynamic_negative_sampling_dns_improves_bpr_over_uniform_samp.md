Yes — uniform random negative sampling is well established to underperform hard/dynamic negative sampling for BPR-style pairwise ranking losses, and Dynamic Negative Sampling (DNS) is the standard cheap fix: for each positive, draw a small pool of N (e.g. 5–32) candidate negatives uniformly (optionally popularity-weighted) from the current minibatch or a light random draw, score just those N with the current model's forward pass, and keep the highest-scoring one as the "hard" negative for the BPR update — this needs only N extra dot-products per positive, not a catalog-wide rescoring pass, so it is CPU/minibatch-friendly. Weinan Zhang et al.'s original SIGIR 2013 paper (DNS) showed this consistently beats uniform BPR on top-N ranking metrics; later theoretical work (Lai et al., WWW 2023, "On the Theories Behind Hard Negative Sampling for Recommendation," arXiv:2302.03472) proves BPR+DNS is an exact estimator of One-way Partial AUC, explaining why it specifically sharpens top-heavy metrics like nDCG@k and GAUC rather than plain AUC. WARP (Weston et al.) is the closely related predecessor that samples until it finds a rank-violating negative rather than picking the max of a fixed pool; DNS(M=1,N) is described in the literature as a simplified, more predictable-cost variant of the same idea. For a KuaiRand-Pure-style sparse, popularity-skewed short-video task, combining DNS's in-pool hard-negative selection with popularity-aware candidate sampling (to avoid always picking globally-popular items as "hard" negatives, which can be false negatives / degenerate) is the commonly recommended cheap recipe; note the same line of work (and follow-ups like Enhanced BPR, arXiv:2403.19276) warns that pushing the pool size N too high increases false-negative risk on very sparse data, so N is typically kept small (≈5–20) precisely to stay cheap and stable on CPU.
